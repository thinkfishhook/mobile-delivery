# Known rough edges

General compatibility fixes and operating constraints are recorded below. Resolved items
link to the change and its acceptance evidence; use a revision containing the relevant fix.
Each app's adoption evidence lives in that app's own repository.

| Applies to | Symptom | Fix belongs in | Resolution |
| --- | --- | --- | --- |
| Any caller | Queued pushes were recognized only for a fixed caller filename. | mobile-delivery | [#6](https://github.com/thinkfishhook/mobile-delivery/issues/6): match the called workflow in `referenced_workflows`; regressions cover arbitrary caller names and unrelated runs. GitHub documents this field in the [repository workflow-runs response](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-repository). |
| Any caller | Release evidence used a caller-specific prefix. | mobile-delivery | [#8](https://github.com/thinkfishhook/mobile-delivery/issues/8): evidence uses `app-store-release-<run>-<attempt>`. |
| Any caller | Runner selection silently defaulted to a machine group. | mobile-delivery | [#12](https://github.com/thinkfishhook/mobile-delivery/issues/12): callers explicitly pass `runs-on`. |
| Any caller | A delayed scheduled release silently skipped on another weekday. | mobile-delivery | [#16](https://github.com/thinkfishhook/mobile-delivery/issues/16): caller schedules determine cadence; all eligibility checks still apply. |
| Any caller | Retry, delivery and pause hints guessed caller filenames. | mobile-delivery | [#7](https://github.com/thinkfishhook/mobile-delivery/issues/7): current workflow hints use `GITHUB_WORKFLOW_REF`; cross-workflow hints use run metadata and fall back to the repository Actions page. |
| Apps with prior versions | Versions such as `2026.06.02`, `1.0`, or malformed revisions could distort comparisons or cause failures. | mobile-delivery | [#18](https://github.com/thinkfishhook/mobile-delivery/issues/18): only YY.MM.RR versions participate in revision, release-history and build comparisons; summaries list ignored versions. Existing drafts and unresolved Apple submissions still require manual resolution. |
| Any caller | Test fixtures and general docs still identified the original app. | mobile-delivery | [#9](https://github.com/thinkfishhook/mobile-delivery/issues/9), [#10](https://github.com/thinkfishhook/mobile-delivery/issues/10): neutral fixture identities, general hold design, and no caller-specific analytics examples. |
| Any caller | Branch, cadence, runner labels and public text had duplicate sources or silent defaults. | mobile-delivery | [#12](https://github.com/thinkfishhook/mobile-delivery/issues/12)–[#16](https://github.com/thinkfishhook/mobile-delivery/issues/16): the README placement table defines ownership; runner labels, release fallback and switches are explicit; branch and schedule come from the caller. |
| Any caller | Configuration and missing credentials failed one at a time or late in a run. | mobile-delivery | [#11](https://github.com/thinkfishhook/mobile-delivery/issues/11), [#17](https://github.com/thinkfishhook/mobile-delivery/issues/17): collect configuration, input, switch and secret-presence problems before operation commands. |
| Any caller | The guide allowed environment-level deployment switches, although App Store guards are evaluated before the environment is available. | mobile-delivery docs | [#22](https://github.com/thinkfishhook/mobile-delivery/issues/22): require repository variables in the setup instructions and placement table, consistent with the existing secrets/variables table and both live apps. [GitHub documents environment-variable availability](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#vars-context). |
| Any caller | A 90-day cutoff silently dropped old closed holds, permitting fresh descendants or retries of pre-fix commits. | mobile-delivery | [#24](https://github.com/thinkfishhook/mobile-delivery/issues/24): read all labelled hold issues and their close events without an age cutoff. Promotion regressions cover old bot/unknown closes, rebuilt pre-fix commits, fixed descendants and person-lifted false alarms. Use a revision containing this fix before enabling App Store automation. |
| Any caller | Lowercase or mixed-case secret references bypassed the signing-secret boundary. | mobile-delivery | [#27](https://github.com/thinkfishhook/mobile-delivery/issues/27): both workflow validators normalize named secret sources before applying allowlists and reject indirect secrets-context access. Regressions cover case variants, wrappers and quoted expression literals. |
| Any caller | P12 and temporary keychain passwords were visible in process arguments. | mobile-delivery | [#26](https://github.com/thinkfishhook/mobile-delivery/issues/26): send one quoted command through `security -i` standard input, with no command log and explicit input limits. Tests cover routing, escaping, refusal and cleanup; a local macOS smoke test passed create/unlock/import/partition operations and wrong-password refusal with a synthetic P12. |
| Apps sharing one runner user | Concurrent signing could restore another job's keychain search list or provisioning profile snapshot. | mobile-delivery | [#28](https://github.com/thinkfishhook/mobile-delivery/issues/28): a persistent per-user file lock spans the complete signing session and cleanup, with an in-process guard. Regressions cover competing processes, process termination, thread contention, and lock ownership during success/failure cleanup. All signing jobs sharing a user must adopt the fix or use separate users. |
| Apps using external TestFlight testers | The tool distributes only to the configured internal group. | Future work | External TestFlight groups are outside v1 scope. Only configured internal-group distribution is supported. |
| Any caller | actionlint does not yet recognize workflow context fields and queued concurrency. | Tooling compatibility | [#21](https://github.com/thinkfishhook/mobile-delivery/issues/21): keep ignores limited to `concurrency.queue`, `job.workflow_sha` and `job.workflow_repository`. Live workflow and queue acceptance are recorded in #20/#21; all other lint findings still fail. |
